## 1. Соглашения

**Все длительности — в календарных днях.** Округление расчётной длительности — **вверх** до целого дня.

### 1.1. Характер файла

Файл представляет собой **справочник фиксированных длительностей**, а не расчётную модель выработки. По всем видам работ, где предполагалась проверка через выработку бригад (СПК, фасады, ВИС, отделка МОП и квартир), получен ответ владельца: **сроки относительно выработки не рассчитываются**.

Практическое следствие для агента: искать выработки для монолита, фасадов, ВИС и отделки бессмысленно — их отсутствие является решением, а не пробелом.

### 1.2. Базовая формула

```
Длительность = Объём / (Выработка × Кол-во ресурсов × Коэф. сменности)
```

Применяется **только к свайному основанию** (§7). Все остальные нормативы заданы фиксированными длительностями либо производны от якорей `bindings.md`.

### 1.3. Приоритет якорных правил

Нормативы **не переопределяют** даты, заданные якорными правилами `bindings.md`. Если расчётное окно между якорями меньше норматива — агент не сжимает норматив, а действует по `BND-OTD-003` (для отделки) или выносит строку в «Допущения» (для прочих работ).

> **Единственное исключение — отделка (§15.2).** Минимум 210 дн жёстче целевого финиша `ЯКОРЬ + 365`: при нехватке окна финиш отделки сдвигается вправо за пределы года, а вместе с ним РВЭ и передача (`DEC-02`, `DEC-09`).

### 1.4. Статусы значений

| Статус | Значение |

| ✅ | Подтверждено владельцем файла |
| ⚠️ | Принято условно, требует калибровки на факте. Уверенность по блоку — не выше средней, строка в «Обосновании» обязательна |
| 🔴 | **Взято из шаблона v2 и отменяет прежнее решение владельца.** Требует подтверждения — `РАСХОЖДЕНИЯ_шаблон_v2.md` §1. Уверенность по блоку — не выше средней, строка в «Допущения» обязательна |

**Позиций без норматива в комплекте нет.** **Скрытых** буферов тоже: после перехода на шаблон v2 резерв блока БИО перестал существовать (§17). ## 5. Ограждение котлована

**STD-ZC-001 · Длительность одинакова для всей очереди** — нулевой цикл общий (`typGRP.md` §10.2)

| Тип ограждения | Длительность |
| --- | --- |
| **Трубошпунт** | 30 дн |
| **СВГ** (стена в грунте) | 50 дн |
| **БСС** (буросекущие сваи) | 60 дн |

Статус: ✅ · Сезонность: нет

### 5.1. Связь с земляными работами

Единая формулировка: **старт ограждения котлована = старт земляных работ + X**, связь НН.

| Тип ограждения | `X` | Смысл |
| --- | --- | --- |
| **Трубошпунт** | **+15 дн** | Ограждение стартует на 15 дн **позже** земляных работ |
| **СВГ** | **−45 дн** | Ограждение стартует на 45 дн **раньше** земляных работ |
| **БСС** | **−45 дн** | То же |

### 5.2. Приращение по корпусам — отменено

🔴 **Каскад стартов фундаментных плит по типу ограждения (`DEC-10`) шаблоном не подтверждается и в расчёте не применяется.**

Прежняя таблица «Сдвиг старта ФП каждого последующего корпуса» (+15 / +20 / +30 / +10 дн по типу ограждения) **упразднена**.

При этом сама плита с редакции шаблона от 02.08.2026 **покорпусная** (§8): у каждого корпуса своя, и её длительность считается по его этажности. Сдвиг старта задаётся связями шаблона, а не нормативом: плита К2 ждёт свайное поле, плита К1 — нет. Позиция остаётся на решении владельца — `РАСХОЖДЕНИЯ_шаблон_v2.md` R-08; строка в «Допущения» обязательна при двух и более корпусах.

## 7. Свайное основание

Единственный блок, рассчитываемый по формуле §1.2.

**STD-ZC-003 · Свайное основание, БНС**
- **1 свая в день** на буровую установку, для любой длины и диаметра
- `Длительность = N_свай / (1 × N_установок)`
- Статус: ⚠️ калибровки не проходило

**STD-ZC-004 · Свайное основание, забивное**
- **10 свай в день** на установку, для любой длины и диаметра
- `Длительность = N_свай / (10 × N_установок)`
- Статус: ⚠️

При наличии обоих типов свай работы ведутся **параллельно**: длительность блока = максимум из двух. При этом длительность каждой дочерней строки равна расчёту именно её типа; максимум не копируется в обе строки (`DEC-35`).

Пример: 35 БНС при 1 установке = **35 дн**; 200 забивных при 1 установке = **20 дн**; длительность параллельного блока = **35 дн**.

> **`DEC-14` · Порог предупреждения — по длительности.** Если расчётная длительность свайного поля **превышает 90 дн**, агент обязан вывести пользователю уведомление и строку в «Допущения» — с расчётной длительностью, её долей в критическом пути и предложением **увеличить число буровых установок**.
>
> Норматив выработки агент самостоятельно не корректирует; менять он может только `N_установок`, и только по решению пользователя.

**STD-ZC-007 · Ростверк** — исключён, учитывается в составе фундаментной плиты.

## 9. Монолит надземной части

**STD-MON-001**

```
Д_монолит = 30 + K × (N − 1) + 15
```

| Позиция | Значение | Статус |
| --- | --- | --- |
| Первый этаж | **30 дн** | ✅ |
| Типовой этаж `K` | **6 дн** | ✅ |
| Типовой этаж `K` при сложном конструктиве **или** `N > 60` | **7 дн** | ✅ |
| Кровля / парапет (монолит) | **15 дн** | ✅ |
| Каскад секций | `НН +7 дн`, **не зависит от числа кранов** | ✅ |

**Технические и верхние этажи отдельно не выделяются** — `K` применяется ко всем этажам со второго.

**Контрольные примеры шаблона v2:**
- К1, 26 этажей, `K = 6` → `30 + 6 × 25 + 15 = 195 дн` ✓
- К2, **55 этажей**, `K = 6` → `30 + 6 × 54 + 15 = 369 дн` ✓

> Второй пример важен: при 55 этажах шаблон применяет `K = 6`, а не 7. Порог `K = 7` наступает только выше 60 этажей либо по признаку «сложный конструктив».

**STD-MON-003 · Монтаж металлических конструкций** — регламентная длительность по шаблону: 60 дн у К1, 300 дн у К2, 120 дн у паркинга. Расчёт по выработке не применяется, значение берётся из шаблона объекта. Статус: ⚠️

## 14. Внутренние инженерные системы

**STD-VIS-001 · ЦТП/ИТП с УУТЭ** — **120 дн** 🔴

| Расположение | Правило |
| --- | --- |
| **При наличии паркинга** | ИТП размещается в паркинге; веха пуска тепла каждого корпуса связывается с ним межобъектной связью |
| **При отсутствии паркинга** | ИТП **разворачивается в каждом корпусе**; поведение шаблоном v2 не покрыто |

Привязка старта — `BND-VIS-006`: **НН от старта отделки технических помещений, лаг +20 дн**.

> 🔴 **Две отмены разом.** Было 200 дн и НН +90 дн от старта кладки перегородок (`DEC-06`, `STD-VIS-001` v2.0). Шаблон v2 даёт 120 дн и НН +20 дн от отделки техпомещений. Обе позиции требуют подтверждения — `РАСХОЖДЕНИЯ_шаблон_v2.md` R-03, R-04.
>

## 17а. Резерв фазы РС→РВЭ

**Решение владельца от 04.08.2026 (`DEC-31`).** До него резерв в комплекте отсутствовал: `DEC-13` упразднил единственный буфер (§17), и график считался только в максимально раннем варианте. Теперь у каждой задачи и вехи фазы B **две даты**, и вторая выводится отдельной колонкой.

### 17а.1. Формула

```
Резерв_дн   = ОКРВВЕРХ( (Дата_окончания − Старт_СМР) / 365 × 30 )
Дата_с_резервом = Дата_окончания + Резерв_дн
```

| Позиция | Значение | Статус |
| --- | --- | --- |
| База отсчёта | **дата начала СМР** проекта (не РС, не старт фазы A) | ✅ |
| Норма резерва | **30 календарных дней на год** возраста вехи (≈8,22 %) | ✅ |
| Округление | вверх до целого дня (§1) | ✅ |
| Задача завершается **раньше** старта СМР | резерв `0`, дата с резервом равна дате окончания | ✅ |

Резерв — **линейная функция удалённости задачи от старта СМР**, а не свойство вида работ. Две задачи с одной датой окончания получают одинаковый резерв независимо от того, к какому блоку относятся.

### 17а.2. Область применения

| Область | Резерв |
| --- | --- |
| Все задачи и вехи фазы B (РС→РВЭ→Передача) | считается |
| Задачи фазы A (до РС) | **не считается** — колонка пуста |
| Задачи фазы B с окончанием раньше старта СМР (ранние договоры на наружные сети) | `0` по формуле |
| Суммарные строки | считается от собственной свёрнутой даты окончания |

Резерв **не сдвигает расчёт**: он не входит в длительности, не участвует в связях и не влияет на критический путь. Ранний график остаётся расчётной моделью, резерв — надстройкой над его результатом. Пересчёт по цепочке от даты с резервом запрещён — иначе резерв накапливается каскадом.

### 17а.3. Подтверждение на утверждённых графиках

Формула выведена из утверждённых карт вех `D:\Claude\ClaudeVS\data` и на них проверена:

| Проект | Вех сверено | Медиана Δ | Доля \|Δ\| ≤ 14 дн |
| --- | --- | --- | --- |
| Южнопортовая 2.1 (49 эт.) | 75 | **0 дн** | 74 / 75 |
| Стрелецкая Офисы (5 эт.) | 67 | −6 дн | 65 / 67 |

На Южнопортовой 2.1 формула воспроизводит утверждённую дату **точно** по 60 вехам из 75. Систематическое смещение −6 дн на Стрелецкой объясняется тем, что там утверждённые даты округлялись вверх до половины месяца — на пятиэтажном объекте с коротким циклом это заметнее, чем на 49-этажном. Расхождение в пределах критерия приёмки `CLAUDE.md` §10 (±14 дн) и корректировки формулы не требует.

Единственное выпадение (`Δ = +90` на «Завершены отделочные работы квартир WB», ЮП 2.1) — незаполненная строка исходной карты: у вехи проставлен резерв 0 при 3 мес у всех соседних. Это дефект источника, а не иная логика.

### 17а.4. Требования к выдаче

- Колонка **«Окончание с резервом»** — в листе «ГРП» и в листе «Карта вех» (`typGRP.md` §2, §14).
- Строка в «Допущения» с кодом `DEC-31` — **всегда**, с указанием принятой базы отсчёта (даты старта СМР) и нормы 30 дн/год.
- В «Обосновании» по каждой ключевой вехе — возраст в днях от старта СМР и полученный резерв, чтобы планировщик проверял арифметику за минуту.
- Уверенность по резерву — **высокая**: норматив подтверждён на двух утверждённых графиках.
