## 1. Соглашения

**Все длительности и лаги — в календарных днях.**

**Финиш достигается только длительностью, никогда ограничением задачи.** Правило вида «финиш = якорь + N» — это правило расчёта длительности: `Длительность = расчётный финиш − расчётный старт`. Ограничения MS Project («Окончание не позднее» и подобные) в графике не появляются.

**Все лаги численны.** Формулировки вида «не менее N» задают требование к процессу, но в график попадает конкретное число.

**Нотация связей — русская.** `ОН` · `НН` · `ОО` · `НО`. Полная таблица и правила записи лага — `typGRP.md` §2.1.

**Правила настоящего файла адресуют задачи-листья.** В шаблоне v2 лист блока СМР — это строка `По договору <наименование>` либо `В соответствии с договорным графиком <наименование>` (`typGRP.md` §10.4). Связь, выведенная правилом `BND-*`, ставится **на неё**, а не на её суммарного родителя. Это не запрет связей у суммарных строк: связи, заданные эталоном на суммарной строке, сохраняются как есть и участвуют в расчёте свёрточным узлом (`typGRP.md` §2.2, `DEC-26`).

**Адресация задач.** Колонки `СДР` в шаблоне v2 нет. Задача адресуется парой «префикс объекта + наименование» (`К1. Монтаж фасадов`), ссылки в графике — только по `Ид.`

**Регламентные блоки здесь не дублируются.** Разделы 3–8, разрешительная документация, подготовительный период, испытания и передача УК, ЗОС/РВЭ берутся из `typGRP.md`.

Формат правила: `Связь · Длительность · Условие · Параметризация · Сезонность · Источник`.

### 1.1. Якоря

| Обозначение | Определение |
| --- | --- |
| `ЯКОРЬ` | **Последний куб бетона корпуса** — финиш задачи «Кровля/Парапет Монолит». Якорь всех финишей фазы B **этого корпуса**. Не путать с завершением последнего типового этажа |
| `ЯКОРЬ_ОЧ` | Последний куб бетона **очереди** = `max(ЯКОРЬ)` по всем корпусам этапа. К нему привязаны агрегирующие вехи раздела 1 и правая часть графика |
| `ЯКОРЬ_ОГР` | Старт кладки наружных стен корпуса. **При отсутствии наружной кладки** (витражи стойка-ригель на всю высоту) — старт монтажа витражей, привязка НН+0 |
| `КЛ_ПАРК` | Финиш кладки паркинга. Точкой отсчёта отделки **больше не является** — редакция шаблона от 02.08.2026 вернула покорпусную привязку (`BND-OTD-002`, `R-09`). Сохранён как якорь отделки техпомещений и монтажа ИТП |
| `TC_perm` | Замыкание постоянного теплового контура корпуса. Зависит от типа фасада — `BND-TC-001` |
| `TC_eff` | Фактически действующий контур = `min(TC_perm, финиш ВТК)`, если ВТК развёрнут; иначе `TC_perm` |
| `Heat` | Плановая дата пуска тепла корпуса — `BND-TC-003` |
| `DL` | Целевой финиш отделки = `ЯКОРЬ + 365 дн` |

**Каждый корпус имеет собственный `ЯКОРЬ`.** На эталоне: К1 — 04.05.2025, К2 — 25.10.2025, `ЯКОРЬ_ОЧ` = 25.10.2025. Финиши ВИС, фасадов, отделки и теплового контура считаются от якоря **своего** корпуса; вехи раздела 1, ЗОС и РВЭ — от самого позднего.

> `DEC-01`: **не менее одного крана на корпус**, при нескольких секциях — один кран на каждые две секции, округление **вверх**. Величина влияет на состав ПОС, но не на даты.

**Пересчёт месяцев в днях:** 1,5 мес = 45 · 4 мес = 120 · 11 мес = 330 · 12 мес = **365**. Значение 365 намеренно принято как календарный год, а не как 12 × 30.

> ⚠ Позиции, где факт шаблона v2 разошёлся с этим пересчётом, закреплены по факту: кладка перегородок — `ЯКОРЬ + 125`, витражи — `ЯКОРЬ + 129` (`РАСХОЖДЕНИЯ_шаблон_v2.md` R-16, R-17).

## 2. Алгоритм расчёта

**Это единственный экземпляр алгоритма в комплекте.** `CLAUDE.md` §7 и `typGRP.md` §12.3 ссылаются сюда и не повторяют шаги.

### 2.1. Общий нулевой цикл — один раз на этап

```
 0. Земляные работы и ограждение котлована                 [BND-ZC-001]
    Свайное основание, длительность standards.md §7        [BND-ZC-002]
    Фундаменты: своя плита каждому корпусу + плита паркинга [BND-ZC-003]
    Монолит ниже 0.000: свой блок каждому корпусу + паркинг
    → веха «Завершены работы по нулевому циклу»
```

Нулевой цикл лежит в блоке паркинга (`typGRP.md` §10.2): земляные работы, ограждение и сваи — общие на очередь, фундаменты и подземный монолит — покорпусные. Каскад стартов ФП по типу ограждения не применяется.

### 2.2. Расчёт корпуса — 13 шагов

```
 1. Монолит поэтажно, длительности standards.md §9         [BND-MON-001]
    При секциях — каскад НН +7 дн                          [BND-MON-002]
 2. Финиш «Кровля/Парапет Монолит» → ЯКОРЬ корпуса
 3. Веха min(6, N) этаж → старт кладки наружных и перегородок
    Определить ЯКОРЬ_ОГР                                   [BND-KLD-001/002]
 4. Веха min(15, N) этаж → старт витражей и ВИС   [BND-SPK-002, BND-VIS-001/002]
 5. ЯКОРЬ_ОГР НН+30 → старт СПК ПВХ                        [BND-SPK-001]
 6. Старт СПК НН+30 → старт фасада                         [BND-FAS-001…003]
    При отсутствии ПВХ: ЯКОРЬ_ОГР НН+30
 7. TC_perm по типу фасада                                 [BND-TC-001]
 8. Проверить необходимость ВТК. Финиш ВТК = финиш кладки  [BND-TC-002]
    наружных стен корпуса, длительность 45 дн
 9. Heat = max(TC_eff, ИТП, финиш отопления-контура) + 15  [BND-TC-003]
10. Старт кладки перегородок НН+90 → S0, сезонный гейт     [BND-OTD-002]
11. Проверить цель 365 дн и жёсткий минимум 210 дн         [BND-OTD-003]
12. Монтаж фасадов ОН−180 → блок БИО                       [BND-BIO-001]
13. Применить сезонность §5
```

**Порядок шагов 8–11 существен.** Решение о ВТК влияет на `TC_eff` → на пуск тепла → на сезонный гейт → на длительность отделки.

**Разрыв круговой зависимости.** Финиш ВТК задан через год старта отделки, а старт отделки зависит от пуска тепла, то есть от самого ВТК. Круг размыкается однопроходно: год берётся из **предварительного** `S0 = старт кладки перегородок + 90` **до** применения сезонного гейта и в дальнейшем не пересматривается. Итерация запрещена — при срабатывании `BND-OTD-003` шаги 9–11 проходятся ровно один раз повторно.

### 2.3. Замыкание очереди

```
14. ЯКОРЬ_ОЧ = max(ЯКОРЬ) по корпусам этапа
15. Агрегирующие вехи раздела 1 — предшественниками все объекты
16. Финиш отделки самого позднего корпуса ОН−160 → готовность к обмерам БТИ  [BND-ZOS-001]
17. Блок ЗОС и РВЭ по этапу, typGRP.md §11
18. Передача помещений от вехи РВЭ                          [BND-PRD-001]
```

## 3. Правила

### 3.1. Нулевой цикл

**BND-ZC-001 · Земляные работы и ограждение котлована**
- Связь: старт ограждения = старт земляных работ + `X`, связь НН; `X` по типу ограждения — `standards.md` §5.1
- Длительности: `standards.md` §5, §6 · Сезонность: нет
- Источник: шаблон, блок «П1. Нулевой цикл»

**BND-ZC-002 · Свайное основание**
- Связь: `ОН − 14 дн` от земляных работ; дополнительно веха «Выдана рабочая документация в производство работ» блока РД на свайное основание
- Длительность: `standards.md` §7, расчёт по выработке
- При наличии обоих типов свай работы ведутся параллельно

**BND-ZC-003 · Фундаменты и монолит ниже 0.000** — покорпусно
- **Своя фундаментная плита у каждого корпуса** плюс отдельная плита паркинга. Длительность плиты — по этажности **своего** корпуса, `standards.md` §8 `STD-ZC-005`
- **Свой блок монолита ниже 0.000 у каждого корпуса** плюс блок паркинга; каждый — `ОН` от **своей** плиты
- Связь плиты со свайным полем в шаблоне стоит не у всех корпусов: у К2 стоит, у К1 нет. Сдвиг старта плиты задаётся этой связью, а не нормативом
- **Надземный монолит каждого корпуса ждёт подземный монолит всех корпусов** — поэтому корпуса стартуют одновременно, по самому позднему
- **Каскад стартов ФП по типу ограждения не применяется** (`DEC-10` отменён, `РАСХОЖДЕНИЯ_шаблон_v2.md` R-08)

### 3.2. Монолит

**BND-MON-001 · Монолит надземной части**
- Связь: ОН от «Монолитные конструкции ниже отм. 0,000», лаг +0
- Длительность: `standards.md` `STD-MON-001`
- Параметризация: развернуть поэтажно, каждый этаж — задача с ОН к предыдущему; последняя задача блока — «Кровля/Парапет Монолит»
- Источник: шаблон, комментарий «стандартный регламент длительности монолитных работ: 1 этаж = 30 дн, типовой этаж = 6 дн, парапет = 15 дн»

**BND-MON-002 · Секции корпуса**
- Связь: НН между секциями, лаг **+7 дн** на каждую следующую
- Каскад **не зависит** от числа кранов; краны — параметр расчёта, не ресурс
- Источник: ответы № 11, 7

### 3.3. Кладка

**BND-KLD-001 · Кладка наружных стен**
- Связь: ОН от вехи «`min(6, N)` этаж Монолит», лаг +0
- Финиш: **`ЯКОРЬ + 45 дн`**
- Условие: конструктив с наружной кладкой. **Не применяется** при витражах стойка-ригель на всю высоту
- Источник: шаблон, комментарий «начало после завершения 6 этажа монолита, завершение через 1,5 мес после завершения монолита последнего этажа»

**BND-KLD-002 · Кладка перегородок**
- Связь: ОН от вехи «`min(6, N)` этаж Монолит», лаг +0
- Финиш: **`ЯКОРЬ + 125 дн`** — факт шаблона v2 у обоих корпусов (комментарий говорит «4 мес»; принят факт, `РАСХОЖДЕНИЯ_шаблон_v2.md` R-16)
- Условие: всегда

> `DEC-04`: кладка стартует после завершения монолита **6 этажа**, а при этажности ниже 6 — **после завершения всего монолита**. Записано как `min(6, N)`.

**BND-KLD-003 · Кладка паркинга**
- Связь: ОН от «Монолитные конструкции ниже отм. 0,000» паркинга; дополнительно `ОН + 60 дн` от вехи заключения договора «Монолит + кладка + кровля стилобата»
- Длительность: `standards.md` §12
- **Финиш кладки паркинга = `КЛ_ПАРК`** — базовая точка отсчёта отделки надземной части всех корпусов (`BND-OTD-002`) и отделки техпомещений (`BND-VIS-004`)

### 3.4. Светопрозрачные конструкции

**BND-SPK-001 · СПК ПВХ (окна)**
- Связь: НН от `ЯКОРЬ_ОГР`, лаг **+30 дн**
- Финиш: `финиш кладки наружных стен + 30 дн` (то есть `ЯКОРЬ + 75 дн`). При отсутствии кладки — `ЯКОРЬ + 129 дн`
- Условие: проект предусматривает ПВХ-остекление · Сезонность: нет
- Источник: шаблон, комментарий «старт через 30 дн после старта кладки наружных стен, завершение через 30 дней после кладки наружных стен»

**BND-SPK-002 · Витражи стойка-ригель**
- Связь: ОН от вехи «`min(15, N)` этаж Монолит», лаг +0
- Финиш: **`ЯКОРЬ + 129 дн`** — факт шаблона v2 (комментарий говорит «4 мес»; принят факт, `РАСХОЖДЕНИЯ_шаблон_v2.md` R-17)
- Условие: проект предусматривает витражное остекление · Сезонность: нет

**BND-SPK-003 · Состав остекления**
- Варианты: только ПВХ · только витражи · оба одновременно. **Указывается в примечании к ТЭП.** При отсутствии указания — остановка (`CLAUDE.md` §12)
- При витражах **на всю высоту** наружная кладка отсутствует → `ЯКОРЬ_ОГР` = старт монтажа витражей
- **На применимость ВТК состав остекления не влияет** (`DEC-05`)
- В эталоне v2 корпуса различаются составом: К1 — ПВХ, К2 — витражи. Оба варианта считаются независимо по своему корпусу

### 3.5. Фасады и кровля

**BND-FAS-001 · Фасад НВФ**
- Связь: НН от старта СПК, лаг **+30 дн**. При отсутствии СПК — НН от `ЯКОРЬ_ОГР`, лаг +30
- Финиш: **`ЯКОРЬ + 330 дн`** · Сезонность: нет
- Источник: шаблон, комментарий «начало через 30 дней после старта монтажа окон ПВХ, завершение через 330 дней после завершения монолита последнего этажа»

> ⚠ У корпуса К2 эталона факт разошёлся с комментарием: старт 14.09.2024 (раньше монолита, без привязки к остеклению), финиш `ЯКОРЬ + 48`. Принято правило комментария, значение шаблона трактуется как ошибка (`typGRP.md` §13 расх. 11).

**BND-FAS-002 · Фасад СФТК (мокрый)**
- Связь и финиш: как `BND-FAS-001`
- Сезонность: **SEA-01**. Старт зимой допустим — утеплитель устраивается при отрицательных температурах; ограничен только финиш

**BND-FAS-003 · Фасад модульный (панельный)**
- Связь: как `BND-FAS-001` · Финиш: `ЯКОРЬ + 210 дн`
- Особенность: **тепловой контур замыкается по завершении модульного фасада**, не по остеклению
- Типового блока задач в шаблоне нет — состав берётся от НВФ, строка в «Допущения» (`typGRP.md` §14 п. 1)

**BND-FAS-004 · Кровля корпуса**
- Связь: ОН от «Кровля/Парапет Монолит»; дополнительно веха заключения договора «Кровля» и веха РД «АР кровля»
- Длительность: `standards.md` §11 · Сезонность: **SEA-02**, коэффициент 2,0
- На эталоне финиш обоих корпусов = `ЯКОРЬ + 60` при длительности 60 дн

**BND-FAS-005 · МОКАП фасада**
- Опережающая задача, **включается в график по умолчанию** (`DEC-12`)
- Связь: ОН от вехи заключения договора «МОКАП фасада»
- Длительность: `standards.md` `STD-FAS-004`
- Является предшественником задачи РД «Корректировка РД по результатам МОКАПа фасадов» — связь сохраняется по каждому корпусу

### 3.6. Тепловой контур

Контрольные даты:

| Дата | Смысл |
| --- | --- |
| **15 октября** | Крайний срок замыкания **постоянного** контура; если не успевает — требуется ВТК |
| **30 октября** | Крайний прогнозный срок пуска тепла, при котором отделку можно начинать в тёплом сезоне того же года |
| **01 апреля** | Начало весеннего окна при переносе старта отделки на следующий год |

**BND-TC-001 · Замыкание постоянного контура (`TC_perm`)** — веха, 0 дн

| Тип фасада | `TC_perm` |
| --- | --- |
| НВФ, СФТК | `max(финиш СПК ПВХ, финиш витражей)` — по остеклению |
| Модульный | `финиш монтажа модульного фасада` |

**BND-TC-002 · Временный тепловой контур (ВТК)** — `DEC-05`
- Старт: `финиш − 45 дн` · Длительность: `standards.md` `STD-TC-001` (45 дн)
- **Финиш ВТК — по финишу кладки наружных стен своего корпуса** (связь `ОО + 0` шаблона). Календарное правило 30 сентября применяется только при отсутствии наружной кладки: замкнуть контур раньше, чем подняты стены, физически нельзя (`R-43`)
- Год старта отделки берётся из предварительного `S0` — §2.2, «Разрыв круговой зависимости»
- Условие: `TC_perm` не замыкается к **15 октября** года отделки, **или** сработала проверка `BND-OTD-003`
- Постоянные СПК планируются в свои регламентные сроки **независимо от ВТК**
- **Отдельная задача демонтажа ВТК не моделируется**

> **Комментарий шаблона исправлен в v2:** «временный тепловой контур возводят при необходимости — в случае если постоянный тепловой контур **не получается** возвести к 15 октября требуемого года». Инвертированное прочтение, действовавшее в комплекте v6.0, больше не требуется.

> ⚠ **Эффект ВТК зависит от календаря проекта, а не от `ЯКОРЬ`.** Развернув ВТК, агент обязан проверить, изменилась ли дата пуска тепла. Если `TC_perm` и без того наступает до 30 сентября либо пуск тепла определяется другим членом формулы `BND-TC-003`, задача ВТК эффекта не даёт и **в график не добавляется**.

**BND-TC-003 · Пуск тепла корпуса** — веха, 0 дн

```
Heat = max( TC_eff , финиш монтажа ИТП , финиш «Отопление — контур для пуска тепла» ) + 15 дн
TC_eff = min(TC_perm, финиш ВТК) при развёрнутом ВТК, иначе TC_perm
```

| Член | Правило | Лаг до вехи |
| --- | --- | --- |
| `TC_eff` | `BND-TC-001`, `BND-TC-002` | **+15 дн** |
| Монтаж ИТП | `BND-VIS-006`. При наличии паркинга ИТП размещается в паркинге, и веха пуска тепла каждого корпуса связывается с ним межобъектной связью | **+15 дн** |
| Отопление — контур для пуска тепла | `standards.md` `STD-VIS-006` | **+15 дн** |

> **Изменение относительно комплекта v6.0.** Прежде член «отопление» входил с лагом `ОН + 0` (`DEC-07`). В шаблоне v2 все три члена входят с `+15 дн`, что видно у обоих корпусов эталона. Позиция отменяет `DEC-07` и вынесена на решение владельца (`РАСХОЖДЕНИЯ_шаблон_v2.md` R-02).

> **`TC_eff` как минимум подтверждён шаблоном.** У корпуса К2 постоянный контур **исключён** из предшественников вехи с комментарием «принимаем пуск тепла по временной схеме, для увеличения длительности отделки». У К1 предшественниками стоят все три члена — на результат это не влияет, поскольку ведущим там оказывается отопление. Применяется прочтение К2.

**BND-TC-004 · Пуск тепла в паркинге** — веха, 0 дн
- Связь: `ОН + 0 дн` от монтажа ИТП, отопления паркинга и наружного теплоснабжения (СМР по договору техприсоединения)
- **Лаг +15 дн к этой вехе не применяется** — в отличие от `BND-TC-003`
- Веха самостоятельная, вехой пуска тепла корпусов не подменяется

### 3.8. Отделка

**BND-OTD-001 · Состав**
В задачу отделки надземной части входит **черновая отделка** — стяжка и штукатурка. По переделам не декомпозируется. Отделка квартир ведётся параллельно с отделкой МОП; внутри квартир — две последовательные задачи: «Подготовка под чистовую отделку» и «Чистовая отделка» со связью `НН + 90 дн`.

**BND-OTD-002 · Старт отделки — сезонный гейт** — `DEC-28`
- Связь: **НН от старта кладки перегородок своего корпуса, лаг +90 дн**. При отсутствии кладки перегородок — НН от `ЯКОРЬ_ОГР`, лаг +90
- Сезонность: **SEA-03**

```
S0 = старт кладки перегородок корпуса + 90 дн
Y  = год, в котором лежит S0

ЕСЛИ Heat ≤ 30 октября года Y:
    Старт = S0                                    # тепло будет в этом сезоне
ИНАЧЕ:
    Старт = min( Heat , 01 апреля года Y+1 )      # «ранее событие»
```

> **Источник формулы — комментарий шаблона v2** к блоку отделки: «старт отделки надземной части через 90 дн после старта кладки (при условии прогноза пуска тепла до 30 октября того же года, иначе **после пуска тепла или 01 апреля следующего года — ранее событие**), завершение через 12 мес после монолита последнего этажа».
>
> Формула проверена на обоих корпусах эталона:
> - **К1**: `S0` = 16.03.2025, `Heat` = 04.11.2025 > 30.10.2025 → старт = `min(04.11.2025, 01.04.2026)`, но ведущим оказывается договор на отделку — 20.03.2025
> - **К2**: `S0` = 16.03.2025, `Heat` = 20.12.2025 > 30.10.2025 → старт = `min(20.12.2025, 01.04.2026)` = 20.12.2025 ✓
>
> Это объясняет и различие в связях: у К2 веха пуска тепла стоит прямым предшественником отделки, у К1 её нет — она не нужна, поскольку ведущей оказалась `S0`.

> **Изменение относительно комплекта v6.0.** Прежде ветка при опоздании тепла давала жёстко 01 апреля следующего года (`DEC-15`). Теперь берётся **более раннее** из двух событий, то есть дата пуска тепла, если она наступает до апреля.
>
> **Точка отсчёта.** Промежуточная редакция шаблона привязывала старт отделки к финишу кладки паркинга (`КЛ_ПАРК`, `ОН + 90`), из-за чего отделка корпуса зависела от чужого объекта. Редакция от 02.08.2026 вернула покорпусную привязку: `НН + 90 дн` от старта кладки перегородок **своего** корпуса — связь и комментарий шаблона теперь совпадают (`РАСХОЖДЕНИЯ_шаблон_v2.md` R-09, R-14).

**BND-OTD-003 · Финиш отделки: цель 365 дней при жёстком минимуме 210** — `DEC-02`, `DEC-09`
- **Целевой** финиш: `ЯКОРЬ + 365 дн` — величина, к которой следует стремиться
- **Жёсткий** минимум длительности: `standards.md` §15.1 — **210 дн**
- Темп отделки при первоначальном планировании **не моделируется**: длительность выводится из даты старта

```
D_min = standards.md §15.1                 # 210 дн, жёсткий
D     = (ЯКОРЬ + 365) − Старт              # окно до целевого финиша

ЕСЛИ D ≥ D_min:
    принять D                              → цель достигнута

ЕСЛИ D < D_min:
    1. развернуть ВТК [BND-TC-002], пересчитать шаги 9–11 алгоритма §2.2
    2. ЕСЛИ новое D ≥ D_min → принять, флаг «отделка под ВТК»
    3. ИНАЧЕ:
         длительность отделки = D_min = 210 дн
         финиш отделки = Старт + 210        # выходит за ЯКОРЬ + 365
         сдвинуть РВЭ и последующие вехи на величину превышения   [DEC-09]
         уведомить пользователя; строка в «Допущения»
```

Контроль на эталоне: К1 — старт 20.03.2025, финиш 08.05.2026, `ЯКОРЬ + 369` · К2 — старт 20.12.2025, финиш 20.10.2026, `ЯКОРЬ + 360`. Обе близки к цели 365 и превышают минимум 210.

| Жёсткое | В окно не планируется, старт переносится по правилу |
| Коэффициент | Планируется, длительность умножается |
| Мягкое | Планируется как есть; при попадании финиша в окно — строка в «Допущениях». График не переделывается |

> `DEC-20`: **коэффициент применяется к попавшей части.** Умножается не вся длительность, а только те календарные дни, что приходятся на окно.
>
> **Расчёт без итераций.** Задача набирает объём работ, равный её базовой длительности в днях. Каждый календарный день **вне** окна засчитывает один день объёма, каждый день **внутри** окна — `1 / коэффициент` дня. Задача финиширует в день, когда объём набран.
