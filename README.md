# Агент 1. Планировщик графика

Рабочая среда агента «Планировщик графика» системы «ИИ-проектный офис» (Level Group).
Пилот — Level Гребной, Этап 1 (выдача в Excel по шаблону ГРП).

## Состав

```
CLAUDE.md                      контракт агента: процесс, выдача, чек-лист §9, границы
instructions/
  typGRP.md                    структура WBS, коды задач, вехи, регламентные сроки фазы A
  bindings.md                  привязки СМР, якоря, лаги, тепловой контур, сезонность
  standards.md                 числовые нормативы длительностей и умолчания
  Шаблон_ГРП.xlsx              эталон структуры: 1 545 задач (1 корпус + 1 паркинг)
tests/
  etalon_TEP.md                вход регрессионного прогона (для человека)
  etalon_project.json          тот же вход в машинном виде — подаётся генератору
  etalon_expected.md           ожидаемый результат и допуски
  template_parsed.json         машинный разбор эталона (генерируется)
tools/
  build_grp.py                 ГЕНЕРАТОР: проект → Excel для импорта в MS Project
  grp_model.py                 расчётное ядро: нормативы, сезонность, тепловой контур, CPM
  parse_template.py            разбор шаблона + сверка статистики typGRP.md §3
  validate_grp.py              валидатор выдачи по машинной части чек-листа §9
  check_regression.py          сверка с эталоном по критериям приёмки §10
  inspect_template.py          разведка структуры xlsx
```

Версии комплекта сверяются между файлами: `CLAUDE.md` v5.1 · `typGRP.md` v2.2 · `bindings.md` v1.3 · `standards.md` v1.2. При расхождении версий агент обязан остановиться (`CLAUDE.md` §0).

## Требования

- Python 3.12+, `openpyxl` (`pip install openpyxl`)
- Git

## Команды

```powershell
# сборка графика
python tools\build_grp.py tests\etalon_project.json out\ГРП_эталон.xlsx

# валидация выдачи по чек-листу §9
python tools\validate_grp.py out\ГРП_эталон.xlsx

# сверка с эталоном по критериям приёмки §10
python tools\check_regression.py out\ГРП_эталон.xlsx

# разбор шаблона и сверка со статистикой typGRP.md §3
python tools\parse_template.py
```

## Конвейер генератора

```
каркас эталона (1 545 строк)
  → устранение расхождений §13 (расх. 9–11)
  → нормативы standards.md по параметрам ТЭП
  → тиражирование корпусов (§12.1)
  → перестройка монолита поэтажно, пересчёт лагов min(6,N) / min(15,N)
  → сетевой расчёт (проход 1)
  → тепловой контур и отделка по каждому корпусу (bindings.md §3.5, §3.7)
  → сетевой расчёт (проход 2)
  → перенумерация Ид., очистка суммарных строк
  → Excel: ГРП · Обоснование · Допущения · Чек-лист · Сценарии
```

Зависимые работы привязываются **связями к вехе монолита кровли** (`ЯКОРЬ`) с численными лагами, а не датами — чек-лист §9. Финиши задаются длительностью, ограничений по дате нет.

## Регрессионный прогон

```powershell
python tools\build_grp.py tests\etalon_project.json out\ГРП_эталон.xlsx
python tools\validate_grp.py  out\ГРП_эталон.xlsx    # ожидается 0 ошибок
python tools\check_regression.py out\ГРП_эталон.xlsx # ожидается 0 нарушений
```

**Пуск тепла — известное расхождение, а не дефект.** Относительно `ЯКОРЬ` расчёт даёт ровно `+170 дн` — ту величину, которую предсказывают `standards.md` §14 (`STD-VIS-001`) и `bindings.md` §3.5 против фактических `ЯКОРЬ + 184`. Это первый кандидат на калибровку норматива ИТП (`typGRP.md` §1.2).

При отклонении разбирается причина в `standards.md` / `bindings.md` / входных данных. **Правка `etalon_expected.md` «под результат» запрещена.**

### Самопроверка валидатора на эталоне даёт 3 ошибки — это норма

Шаблон не является выдачей агента. Ошибки воспроизводят задокументированные расхождения `typGRP.md` §13:

| Ошибка | Расхождение |
| --- | --- |
| 370 суммарных строк с собственными данными | норма для шаблона; в выдаче запрещено (§2.2 п.4) |
| 12 разрывов в столбце `Ид.` | §13 расх. 9 |
| 3 связи на несуществующие `Ид.` | §13 расх. 10 |

Выдача агента обязана проходить валидатор **без ошибок**.

## Ограничения текущей версии генератора

| Ограничение | Причина |
| --- | --- |
| **84 задачи-листа удерживаются календарной датой шаблона** | В эталоне у них нет предшественников. Это помеченные ограничения (`CLAUDE.md` §9 допускает «согласованные и помеченные»); при поступлении правил привязки заменяются связями |
| **Критический путь охватывает 14 задач** и не дотягивается до старта проекта | Прямое следствие предыдущего пункта: цепочка обрывается на календарном якоре блока ЗОС. Сам путь непрерывен |
| **Регламентные блоки фазы A наследуют длительности шаблона** | Так предписано `typGRP.md` §6.0 — пересчёту по `standards.md` они не подлежат |
| **Тиражирование корпусов не подтверждено владельцем** | `typGRP.md` §14 п.8: правила нумерации `11.4.N` и состав вех при 3+ корпусах. Механизм реализован, строка в «Допущения» выводится |
| **Сценарии не считаются** | `DEC-16`, правила не заданы |

Проверено на краевых случаях этажности: 4 этажа (кладка → этаж `min(6, 4) = 4`, `DEC-04`), 26 этажей (195 дн — контрольный пример `standards.md` §9), 52 этажа со сложным конструктивом (`K = 7 дн`).
