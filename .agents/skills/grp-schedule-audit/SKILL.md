# Аудит графика ГРП

## Режим

Работай только на чтение. Не исправляй файлы и не создавай новую версию, пока пользователь явно не попросит внести изменения.

## Контекст

1. Полностью прочитай `instructions/typGRP.md`, `instructions/bindings.md` и `instructions/standards.md` и сверь их версии с `AGENTS.md`.
2. Открывай `РАСХОЖДЕНИЯ_шаблон_v2.md`, только когда нужно проверить конкретное применение `R-*` или трассировку решения.
3. Не считай Excel-шаблон и калибровочные MPP источниками нормативов.

## Проверка

- Для Schedule IR вызови `schedule_summary`, затем `schedule_validate_ir`.
- Для MPP вызови `mpp_validate`. Если доступен соответствующий IR, обязательно передай его для точной сверки; без IR явно обозначь, что выполнена только структурная проверка.
- Для Excel используй `tools/validate_grp.py` и отдельно проверь обязательные листы, формат, карты вех, «Обоснование» и «Допущения».
- Разделяй ошибки, предупреждения, неподтверждённые условия и допустимые отклонения по `DEC-*`/`R-*`.
- Отдельно проверь открытые концы сети, недопустимые типы связей, отрицательные резервы, несвязный критический путь и сохранность корпоративного шаблона/полей MPP.

## Отчёт

Начни с вывода «годен / годен с замечаниями / не годен». Затем перечисли проблемы по критичности с идентификатором задачи или строки, фактическим значением, требованием и источником правила. Заверши минимальным планом исправления, не выполняя его автоматически.
