# Агент 1. Планировщик графика

Рабочая среда агента «Планировщик графика» системы «ИИ-проектный офис» (Level Group).
Пилот — Level Гребной, Этап 1 (выдача в Excel по шаблону ГРП).

> **02.08.2026 — комплект и генератор приведены к текущей редакции `Шаблон_ГРП v2.xlsx`.** Владелец разбил фундаменты и подземный монолит по корпусам и исправил привязку старта отделки. Конвейер собирается, валидируется без ошибок и проходит **все четыре** жёстких критерия приёмки.

## Команды

Без выходного пути создаётся пара Excel + Schedule IR с новым уникальным именем
на рабочем столе текущего пользователя (в облаке — в `artifacts/output`):

```powershell
python tools\output_paths.py
python tools\build_grp.py tests\etalon_project.json
```

Ниже — прежние команды с **явными** путями в `out/`, оставленные для
регрессионных прогонов. Существующие результаты не перезаписываются.

```powershell
# разбор шаблона и сверка со статистикой typGRP.md §3
python tools\parse_template.py

# сборка графика
python tools\build_grp.py tests\etalon_project.json out\ГРП_эталон.xlsx

# сборка Excel и дополнительного Schedule IR JSON
python tools\build_grp.py tests\etalon_project.json out\ГРП_эталон.xlsx --ir out\ГРП_эталон.ir.json

# создание нового MPP из Schedule IR (существующий MPP не перезаписывается)
python tools\mspdi_adapter.py out\ГРП_эталон.ir.json out\ГРП_эталон.mpp

# проверка сети MPP и точная сверка с исходным Schedule IR
python tools\mpp_validator.py out\ГРП_эталон.mpp --ir out\ГРП_эталон.ir.json --json-report out\ГРП_эталон.mpp-report.json

# локальный MCP-сервер (обычно запускается самим Codex)
python tools\mcp_server.py

# валидация выдачи по чек-листу §9
python tools\validate_grp.py out\ГРП_эталон.xlsx

# сверка с эталоном по критериям приёмки §10
python tools\check_regression.py out\ГРП_эталон.xlsx

# юнит-тесты генератора
python -m pytest tests -q
```

Подключение MCP к Codex и описание доступных инструментов —
[`docs/mcp-codex.md`](docs/mcp-codex.md).

## Работа с двух ПК и хранение результатов

В Git хранятся код, инструкции, skills, тесты и шаблоны конфигурации.
Готовые графики, облачная выдача, секреты и локальные настройки исключены через
`.gitignore`. Desktop каждого ПК независим: Git не переносит графики между ПК.

1. Общий репозиторий: [agent1-planner](https://github.com/kubalovaeisam15/agent1-planner).
   По решению владельца он публичный. Remote `origin` указывает на
   `https://github.com/kubalovaeisam15/agent1-planner.git`, рабочая ветка — `master`.
   Перед commit и push проверяйте `git status` и состав изменений: не добавляйте
   секреты, локальные настройки и входные данные реальных проектов.
2. На втором ПК выполните `git clone https://github.com/kubalovaeisam15/agent1-planner.git`
   в удобную папку. Перед работой
   обновляйте код через `git pull --ff-only`; собственные изменения сохраняйте
   отдельным commit и отправляйте через `git push`. Не переносите абсолютные
   пути первого ПК.
3. На каждом ПК установите Python 3.12+, `openpyxl`, `pytest`. Корпоративный
   `data/Шаблон ГРП.mpp` хранится в Git и появляется в нужной папке при клонировании.
   Остальные файлы `data/` исключены из Git. Не изменяйте шаблон и не заменяйте
   его результатом экспорта: каждый MPP создаётся на основе полной копии шаблона.
   Для MPP нужен установленный Microsoft Project и Windows COM.
4. Из корня проекта запустите `powershell -File setup/install.ps1`.
   Установщик определит Python и путь репозитория на этом ПК и создаст локальные
   `.codex/config.toml`, `.codex/hooks.json`, `.mcp.json`. Они не должны
   отслеживаться Git; код hooks и `hooks.template.json` остаются в репозитории.
   Уже имеющиеся локальные настройки не копируйте с другого компьютера.
5. Перезапустите сессию и вызовите `context_preflight`: нужны `ready: true` и
   ожидаемый `output_dir`. Корень репозитория определяется расположением модуля,
   а не текущим рабочим каталогом.

Выбор папки реализован в `tools/output_paths.py:get_output_dir()`:

| Настройка | Результат |
| --- | --- |
| `AGENT1_RUNTIME=auto` (умолчание) | Существующий Desktop; при `CI=true/1/yes` или отсутствии Desktop — `<repo>/artifacts/output` |
| `AGENT1_RUNTIME=local` | Только существующий Desktop; если его нет — понятная ошибка |
| `AGENT1_RUNTIME=cloud` | Всегда `<repo>/artifacts/output`, без обращения к Desktop |
| `AGENT1_DESKTOP_DIR` | Необязательный абсолютный путь рабочего стола; переменные окружения раскрываются без запуска команд |

Desktop ищется через `AGENT1_DESKTOP_DIR`, затем `XDG_DESKTOP_DIR`, настройку
Windows User Shell Folders (в том числе перенаправление OneDrive), затем
`USERPROFILE/Desktop`, `HOME/Desktop` или профиль ОС. Несуществующий Desktop
не создаётся автоматически. Относительные пути и нераскрытые переменные
отклоняются; ошибки доступа не маскируются перенаправлением в другую папку.
Разрешения ОС и sandbox действуют независимо от helper: он их не расширяет.

Для **Codex Cloud** явно задайте `AGENT1_RUNTIME=cloud` в окружении запуска.
Это настройка нашего проекта, а не предположение о служебной переменной Codex.
В Linux shell можно запустить:

```sh
AGENT1_RUNTIME=cloud python tools/build_grp.py tests/etalon_project.json
```

На Windows проверка того же режима:

```powershell
$env:AGENT1_RUNTIME = 'cloud'
python tools\build_grp.py tests\etalon_project.json
Remove-Item Env:AGENT1_RUNTIME
```

`.env.example` — только образец: файл `.env` автоматически не загружается.
До завершения облачной среды заберите `artifacts/output` через доступный
механизм скачивания/выгрузки артефактов. Эта папка игнорируется Git, поэтому
обычный commit/push её не переносит. Автоматическая выгрузка здесь не настроена.
Excel и IR создаются без Microsoft Project; MPP и его COM-валидацию нужно
доделать на Windows. Такой облачный результат — частичная выдача, не полный ГРП.

MCP `schedule_build` принимает только `spec_path` и сам выбирает новые имена
Excel и IR. `mpp_export` также допускает отсутствие `mpp_path`. Для отчётов
и других конечных файлов используйте `output_dir`, возвращённый preflight.
Явные пути сохраняют прежнее поведение: относительные считаются от корня
репозитория. MCP допускает результаты только внутри репозитория или выбранной
папки выдачи, проверяет разрешённые границы после разрешения ссылок и запрещает
перезапись. Входные ТЭП и MPP-шаблоны по-прежнему ограничены репозиторием.

Проверка выбора папки и совместимости:

```powershell
python -m pytest tests/test_output_paths.py tests/test_mcp_server.py -q
```

## Что изменил шаблон v2

Полный разбор — `РАСХОЖДЕНИЯ_шаблон_v2.md`. Коротко:

**Формат.** Колонки `СДР` больше нет — точечные коды вида `11.4.2.1.8` упразднены. Иерархию несёт только `Уровень структуры`, который теперь подаётся самим шаблоном. Добавлены пустые колонки `Вид работ` и `Код классификатора` — заготовка под справочник МДМ. Строка «Наименование проекта» удалена. Итого 12 колонок вместо 10.

**Структура.** Задачи СМР адресуются префиксом объекта (`П1.`, `К1.`, `К2.`). Появился уровень этапа ввода: «СМР 1-й Этап», «ЗОС и РВЭ → 1-й Этап». Нулевой цикл лежит в блоке паркинга: земляные работы, ограждение и сваи — общие на очередь, **фундаменты и подземный монолит — покорпусные**. Тендерных блоков СМР 48 вместо 53.

**Эталон.** Проект стал двухкорпусным: К1 — 26 этажей, К2 — 55. РС не изменилась (02.04.2024), РВЭ сдвинулось с 22.06.2026 на **31.12.2026**, фаза РС → РВЭ выросла с 811 до **1 003 дней**.

**Отменённые решения владельца.** Шаблон v2 переопределил `DEC-05`, `DEC-06`, `DEC-07`, `DEC-08`, `DEC-10`, `DEC-13`, `DEC-15` и норматив `STD-VIS-001`. Комплект пересчитан по значениям шаблона, каждая позиция помечена статусом 🔴 и требует подтверждения (`РАСХОЖДЕНИЯ_шаблон_v2.md` §7).

**Закрытые вопросы.** Инверсия комментария ВТК исправлена в самом шаблоне; `TC_eff = min(TC_perm, ВТК)` подтверждён поведением К2; финиш ВИС `ЯКОРЬ + 330` (`DEC-23`) подтверждён явным комментарием.
