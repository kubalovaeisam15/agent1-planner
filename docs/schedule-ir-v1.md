# Schedule IR v1.0

Schedule IR — внутренний, не зависящий от формата файла контракт расписания.
Planning logic рассчитывает график один раз; Excel, Microsoft Project и MCP
получают данные из одной модели и не реализуют правила планирования повторно.

```text
Вход проекта → Planning logic / CPM → Schedule IR → Excel
                                            ├────→ Microsoft Project / MPP
                                            └────→ MCP API
```

На переходном этапе существующий Excel-адаптер продолжает получать готовые
строки ГРП напрямую. Функция `schedule_from_grp()` строит из тех же строк IR;
тесты контролируют эквивалентность. Перевод Excel на IR выполняется отдельным
шагом после стабилизации контракта.

JSON создаётся только по явному параметру и не меняет прежнюю команду сборки:

```powershell
python tools\build_grp.py tests\etalon_project.json out\ГРП.xlsx --ir out\ГРП.ir.json
```

Перед записью вызывается `validate_schedule_ir()`. При нарушении контракта
команда завершается с ошибкой и не записывает Excel или IR.

## Корневой объект

| Поле | Смысл |
| --- | --- |
| `schema_version` | Версия контракта, сейчас `1.0` |
| `schedule_id` | Стабильный идентификатор расписания; берётся из `project_id` или вычисляется детерминированно |
| `name` | Пользовательское название проекта |
| `project_start` | Дата начала в ISO `YYYY-MM-DD` |
| `calendars` | Календари проекта |
| `tasks` | Задачи в порядке WBS |
| `metadata` | Происхождение, язык и семантика дат |

## Задача

| Поле | Смысл |
| --- | --- |
| `task_id` | Идентификатор задачи внутри расписания |
| `source_key` | Стабильный внутренний ключ исходной строки генератора |
| `parent_id` | Родитель WBS; `null` только у корневых строк |
| `name` | Исходное русское наименование без перевода |
| `outline_level` | Уровень WBS, начиная с 1 |
| `task_type` | `summary`, `task` или `milestone` |
| `phase` | `A`, `B` или `null` |
| `duration_days` | Длительность в календарных днях; у summary — `null`, у milestone — `0` |
| `start`, `finish` | Расчётные даты ISO |
| `reserve_finish` | Дата с резервом DEC-31 либо `null` |
| `percent_complete` | Процент завершения; у summary — `null` |
| `critical` | Признак критической задачи |
| `calendar_id` | Ссылка на календарь |
| `notes` | Комментарий и трассировка правила |
| `predecessors` | Входящие логические связи |

## Связь

`predecessor_id` указывает на существующую задачу. Поле `type` использует
международную нотацию, а `lag_days` — целое число календарных дней.

| ГРП | Schedule IR | Смысл |
| --- | --- | --- |
| `ОН` или код отсутствует | `FS` | окончание → начало |
| `НН` | `SS` | начало → начало |
| `ОО` | `FF` | окончание → окончание |
| `НО` | `SF` | начало → окончание |

## Календарь и даты

IR v1.0 фиксирует текущую семантику генератора: длительности и лаги измеряются
в календарных днях, `finish = start + duration_days`. Базовый календарь
`calendar-7d` содержит все семь рабочих дней. MPP-адаптер обязан сохранить эту
семантику и не переводить длительности молча в стандартную пятидневную неделю.

## Валидация

`validate_schedule_ir()` проверяет:

- версию схемы и уникальность идентификаторов;
- целостность WBS и порядок родителей;
- типы задач, длительности и даты;
- наличие календарей и предшественников;
- типы связей, самоссылки и циклы;
- непротиворечивость даты с резервом.

Валидатор не пересчитывает расписание и не заменяет предметный валидатор ГРП.
Он проверяет только целостность транспортного контракта.

`reserve_finish` сохраняется в Excel и Schedule IR для аналитики, но не
переносится в поле `Deadline` Microsoft Project. По DEC-31 резерв не участвует
в связях и не влияет на критический путь; `typGRP.md` §2 исключает эту колонку
из импорта в Project.

При создании MPP используется корпоративный файл `data/Шаблон ГРП.mpp`.
Выходной файл сначала создаётся как полная копия этого MPP, а затем внутри
копии заменяются только строки задач. Поэтому локальные корпоративные поля,
представления, таблицы, фильтры, группы и календари остаются частью самого
выходного файла, а не переносятся выборочно через Organizer. Перед сохранением
экспорт сверяет каждый из этих наборов с исходным шаблоном и останавливается
при любой потере. Исходный шаблон не открывается для записи и не изменяется.

## Границы v1.0

Пока не входят в контракт: ресурсы и назначения, стоимость, базовый план,
фактические даты, несколько календарей, ограничения MS Project и пользовательские
поля MPP. Они добавляются версионированно после MVP чтения/записи MPP.
